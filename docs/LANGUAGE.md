# Язык PuginScript

Документация по языку: лексика, синтаксис, семантика и модель исполнения. Краткое описание проекта находится в [корневом README](../README.md), архитектура транслятора -- в [ARCHITECTURE.md](ARCHITECTURE.md), описание целевой системы команд -- в [ISA.md](ISA.md)

## Типы данных

- `int` -- 32-битное знаковое целое
- `bool` -- логическое значение, литералы `true` и `false`
- `str` -- указатель на null-terminated строку в памяти данных; индексация `s[i]` при `0 <= i < len(s)` даёт код байта (`int`), чтение терминатора `s[len(s)]` даёт `0`, любой другой индекс вызывает trap 4; изменять строку по индексу нельзя

Отдельного символьного типа нет: код символа -- обычный `int` (ASCII, 0-255)

## Лексика

- идентификаторы: латинские буквы, цифры (не первым символом) и `_`; регистр значим
- целочисленные литералы -- последовательности цифр, могут содержать символы подчёркивания для читаемости (`1_000_000`); диапазон -- `-2147483648`-`2147483647`. Знак числа не входит в литерал: по грамматике литерал -- всегда неотрицательная последовательность цифр, а минус перед числом -- унарный оператор. Поэтому литерал `2147483648` допустим только как операнд унарного минуса, в составе выражения `-2147483648` (стиль Java), а `2147483648` вне унарного минуса -- ошибка компиляции; кроме того, выражение `-2147483648` не может стоять слева от `**`
- строковые литералы в двойных кавычках, символьные -- в одинарных
- escape-последовательности: `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`
- комментарии: `//` до конца строки и `/* ... */` без вложенности; вырезаются лексером до разбора
- ключевые слова: `int`, `bool`, `str`, `if`, `else`, `while`, `def`, `return`, `include`, `const`, `true`, `false`, `new`

## Модель исполнения и точка входа

- если в программе есть `main`, исполнение начинается с её вызова; процедура `def main()` завершается с кодом `0`, а `def main() -> int` должна вернуть значение, которое становится кодом завершения (exit code)
- при наличии `main` сохраняются объявления функций и `const`; все остальные объявления и операторы верхнего уровня разбираются и проверяются компилятором, но не попадают в машинный код, не выделяют память и не выполняются
- верхнеуровневые переменные недоступны из функций независимо от режима запуска; состояние программы хранится в локальных переменных и параметрах
- если `main` нет, программа исполняется как скрипт сверху вниз, включая объявления переменных и их инициализаторы
- функция без `-> type` является процедурой: она может завершиться без `return` или выполнить `return;`; функция с `-> type` обязана вернуть значение объявленного типа на каждом возможном пути, иначе это ошибка компиляции
- `return` на верхнем уровне завершает программу; без выражения -- с кодом 0
- операторы верхнего уровня, объявления переменных и функций могут чередоваться в любом порядке

## Операторы и приоритеты

1. `primary` (литералы, вызовы, `new`, `(expr)`)
2. `**` (возведение в степень)
3. `!`, `-` (унарные операции)
4. `*`, `/`, `%` (умножение, деление, остаток)
5. `+`, `-` (сложение, вычитание)
6. `==`, `!=`, `<`, `<=`, `>`, `>=` (сравнение)
7. `&` (логическое И)
8. `|` (логическое ИЛИ)

`&` и `|` всегда вычисляют оба операнда, в том числе внутри условия. `+` складывает два `int`; если один из операндов имеет тип `str`, второй скалярный операнд (`int` или `bool`) преобразуется в текст, после чего строки объединяются. Числа записываются десятично, логические значения -- как `true` и `false`. Результат конкатенации имеет тип `str` и выделяется в куче. Конкатенация массивов не поддерживается.

Условия `if` и `while` должны иметь тип `bool`.

Операторы `==` и `!=` сравнивают строки по содержимому: байты проверяются последовательно до первого несовпадения или завершающего `\0`. Сравнение адресов строк не используется. Сравнение массивов через `==` и `!=` в первой версии запрещено. Остальные операторы сравнения применяются к `int`.

Составное присваивание (`+=`, `-=`, `*=`, `/=`, `%=`) определено только для `int`; для строк возможно только `s = s + t`.

Скобки вокруг цели присваивания допустимы и игнорируются: `(x) = 5` эквивалентно `x = 5`

Арифметические операции над `int` оставляют младшие 32 бита результата. Например, переполнение `2147483647 + 1` даёт `-2147483648`. Деление усекает частное к нулю, как в C и Java, а остаток имеет знак делимого: `-7 / 2 = -3`, `-7 % 2 = -1`. Деление на ноль вызывает runtime trap; `INT_MIN / -1` переполняет 32 бита, частное считается побитово и даёт `INT_MIN`, остаток `0`.

## Включение файлов и константы

- `include "relative/path/to/file.ps";` -- парсер ищет файл относительно файла с директивой, отдельно лексирует и разбирает его, затем вставляет полученные элементы программы на место директивы; путь должен быть относительным (без `..` и указания диска) и оканчиваться на `.ps` или `.h`; включения ведут только вниз по дереву исходников, чтобы программа оставалась самодостаточной
- повторное включение файла считается ошибкой, в том числе при циклическом включении; все файлы используют единое глобальное пространство имён
- `const int day_s = 24 * hour_s;` объявляет compile-time-константу; она может ссылаться на ранее объявленные константы
- инициализатор `const` вычисляется при компиляции и не может вызывать функции, использовать `new` или индексацию; константы неизменяемы и не создают исполняемого кода
- поддерживаются скалярные `int`, `bool` и `str`; инициализатор `str` -- строковый литерал или ранее объявленная `const str`, конкатенация строк на этапе компиляции не выполняется; массивы констант не поддерживаются
- повторное объявление имён, включая функции `main` и константы, -- ошибка компиляции

## Области видимости

- объявление переменной действует до конца ближайшего `{}` блока
- повторное объявление того же имени в одном блоке -- ошибка компиляции; переприсваивание -- обычный assignment
- **ссылочная семантика**: переменные типов `str` и `int[]` (и других массивов) хранят не само значение, а адрес в куче. Присваивание (`a = b`) копирует адрес, а не данные (алиасинг)
- литерал массива, например `int[] array = [1, 2, 3];`, создаёт массив в куче; элементы должны соответствовать объявленному типу массива. Пустой литерал не поддерживается, для массива нулевой длины используется `new int[0]`
- объявление без инициализатора само по себе не делает чтение переменной допустимым: семантика выдаёт ошибку при чтении до первого присваивания; кодогенератор всё равно записывает ноль в локальный слот как техническое начальное содержимое памяти
- функции принимают скаляры (`int`, `bool`) по значению, а массивы и строки -- по ссылке. Изменение элементов массива внутри функции отразится на оригинале

## Ввод-вывод

Обмен с внешним миром идёт через PMIO (Port Mapped I/O): операция ввода -- чтение из порта ввода, операция вывода -- запись байта в порт вывода. Семантика встроенных функций:

- `print(x)` -- вывод значения без перевода строки: `str` -- байты до терминатора `\0`, `int` -- десятичная запись со знаком, `bool` -- `true` или `false`. Семантика взята из Java (`System.out.print`)
- `println(x)` -- то же, что `print`, но с переводом строки `\n` в конце; вызов `println()` без аргументов выводит только `\n`. Семантика взята из Java (`System.out.println`)
- `print_char(int)` -- вывод одного байта по коду символа (0-255)
- `len(x)` -> `int` -- возвращает количество элементов в массиве или длину строки (без учёта `\0`)
- `input()` -> `str` -- читает строку до `\n` или `\r` и возвращает её без завершающего `\n`/`\r`; на каждый вызов в куче выделяется буфер 1024 байта, включая завершающий `\0` (максимум 1023 байта текста); если входной поток исчерпан, модель останавливается
- `input_int()` -> `int` -- читает строку целиком и интерпретирует её как 32-битное знаковое число; строка, не являющаяся корректным числом или не влезающая в 32 бита, -- trap
- `input_char()` -> `int` -- код одного символа (0-255)

EOF -- исчерпание входного потока. По варианту `stream` при чтении из пустого входного буфера модель процессора останавливает моделирование с пометкой причины в журнале. Отдельного значения EOF в языке поэтому нет: `input` и `input_int` не возвращают признак конца, `input_char` никогда не даёт `-1` (байты данных -- 0-255). Потоковые программы вроде `cat.ps` -- бесконечный цикл чтения и вывода; их исполнение завершает модель, а не сама программа

## Ошибки

### Ошибки компиляции

Транслятор проверяет всё, что выводимо из текста программы, ещё до запуска: синтаксис и типы, повторные объявления имён, отрицательные константные размеры `new`, литералы `int` вне 32-битного диапазона и переполнение статической памяти для данных, которые попадут в программу. Верхнеуровневый код в программе с `main` также проверяется, хотя не попадает в машинный код. При любой ошибке компиляции `.bin` не создаётся

### Ошибки времени исполнения (runtime errors)

Класс ошибок, который нельзя поймать по тексту программы: их проявление зависит от входных данных и порядка исполнения. Механизм -- trap: симулятор останавливается, печатает причину и дамп состояния машины. Ожидаемые случаи:

- индекс вне границ массива или строки
- отрицательный размер массива в `new` при динамическом значении
- превышение предельного размера массива или столкновение кучи и стека при динамическом выделении памяти (`new`, `input()`, конкатенация строк)
- деление на ноль
- возведение в отрицательную степень (`a ** b` при `b < 0`)
- строка для `input_int()` не является корректным 32-битным знаковым числом
- строка для `input()` содержит больше 1023 байт текста

Исчерпание входного потока -- не trap: при чтении из пустого буфера модель процессора останавливает моделирование и фиксирует причину в журнале (вариант `stream`)
