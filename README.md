## Язык программирования

PuginScript -- императивный, строго типизированный, компилируемый язык программирования. Полная документация -- в [docs/LANGUAGE.md](docs/LANGUAGE.md).

Язык -- гибрид концепций из классических и современных языков:
- **C:** использование фигурных скобок `{}` для блоков кода, обязательных символов `;`, семантика передачи аргументов по значению, реализация строк как null-terminated последовательностей байт и соглашение об использовании `snake_case`
- **Python:** функция `input()`, использование ключевого слова `def` для объявления функций и модель исполнения кода верхнего уровня без необходимости функции `main`. Отсюда же заимствован оператор возведения в степень `**`
- **Java:** имена и семантика функций вывода `print` и `println`, конкатенация строк через `+` с преобразованием скалярных значений в текст, а также ссылочная семантика для массивов (передача в функции по ссылке, создание через `new`)
- **TypeScript:** строгая статическая типизация данных и синтаксис объявления переменных

### Ключевые особенности
- **Типы данных:**
  - `int` -- 32-битное знаковое целое
  - `bool` -- логическое значение
  - `str` -- указатель на null-terminated строку в памяти
- **Ветвления:** `if / else`
- **Циклы:** единственный тип цикла -- `while`. Отсутствие `for`, `break`, `continue` и `goto` упрощает транслятор и гарантирует соблюдение принципа *SESE -- Single Entry, Single Exit*, что делает логику программы предсказуемее и легче для анализа
- **Функции:** объявление через ключевое слово `def`, поддержка рекурсивных вызовов
- **Ввод-вывод:** PMIO (Port Mapped I/O) и встроенные функции `input()`, `input_int()`, `input_char()`, `print()`, `println()`, `print_char()`, `len()`

### Семантика

- стратегия вычислений строгая: операнды вычисляются до применения операции; `&` и `|` всегда вычисляют оба операнда, короткого замыкания нет
- области видимости блочные: объявление действует до конца ближайшего блока `{}`; повторное объявление того же имени в одном блоке -- ошибка компиляции
- типизация статическая и строгая; неявных преобразований между скалярными типами нет, скаляр превращается в текст только при конкатенации со `str` и в функциях вывода
- аргументы передаются по значению для скаляров и по ссылке для массивов и строк (копируется адрес в куче)
- литералы: десятичные целые, строковые в двойных кавычках (escape-последовательности `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`), символьные в одинарных, логические `true` и `false`

Подробности и полные правила -- в [docs/LANGUAGE.md](docs/LANGUAGE.md#области-видимости)

### Модель исполнения и точка входа

PuginScript поддерживает гибкую модель исполнения (top-level и функция `main`):

- **при наличии функции `main`**: транслятор автоматически делает её точкой входа. Объявления функций и `const` сохраняются; остальной код верхнего уровня проверяется, но не генерируется и не выполняется. Программа начинает выполнение с вызова `main()`; результатом программы становится значение, возвращённое `main` (`0`, если `main` -- процедура)
- **при отсутствии `main`**: программа исполняется как скрипт сверху вниз
- `return` на верхнем уровне завершает программу с переданным значением (по умолчанию `0`)
- то, как результат программы превращается в код `halt`, описано в разделе «Организация памяти»

### Ввод-вывод

Обмен с внешним миром идёт через PMIO (Port Mapped I/O): ввод -- чтение из порта, вывод -- запись байта в порт. Встроенные функции: `print(x)` и `println(x)` -- вывод без и с переводом строки (семантика из Java), `print_char(int)` -- вывод одного байта, `input()`, `input_int()`, `input_char()` -- ввод строки, числа и символа. Полная семантика, включая поведение при EOF, -- в [docs/LANGUAGE.md](docs/LANGUAGE.md#ввод-вывод)

### Препроцессор и включение файлов

Для включения исходного файла используется директива:

```python
include "relative/path/to/file.ps";
```

- файл ищется относительно файла с директивой; парсер отдельно лексирует и разбирает его, затем вставляет полученные элементы программы на место директивы; путь должен быть относительным (без `..` и указания диска) и оканчиваться на `.ps` или `.h`; включения ведут только вниз по дереву исходников, чтобы программа оставалась самодостаточной
- повторное включение файла считается ошибкой, в том числе при циклическом включении
- включённые файлы образуют единое пространство имён; повторное объявление одинаковых имён (включая две функции `main`) является ошибкой компиляции
- объявления `const` из включённых файлов доступны во всей программе без выполнения верхнеуровневого кода

## Синтаксис (EBNF)

```ebnf
program = { include_stmt | const_decl | statement | function_decl } ;

include_stmt = "include" string_literal ";" ;
const_decl = "const" base_type identifier "=" expression ";" ;

function_decl = "def" identifier "(" [ param_list ] ")" [ "->" type ] block ;
param_list = param { "," param } ;
param = type identifier ;

block = "{" { statement } "}" ;

statement = var_decl ";"
          | assignment ";"
          | if_stmt
          | while_stmt
          | return_stmt ";"
          | expression ";"
          | block ;

var_decl = type identifier [ "=" expression ] ;
assignment = lvalue ( "=" | "+=" | "-=" | "*=" | "/=" | "%=" ) expression ;
lvalue = identifier [ "[" expression "]" ] ;

if_stmt = "if" "(" expression ")" block [ "else" ( if_stmt | block ) ] ;
while_stmt = "while" "(" expression ")" block ;
return_stmt = "return" [ expression ] ;

expression = logical_or ;
logical_or = logical_and { "|" logical_and } ;
logical_and = comparison { "&" comparison } ;
comparison = term [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) term ] ;
term = factor { ( "+" | "-" ) factor } ;
factor = unary { ( "*" | "/" | "%" ) unary } ;
unary = ( "!" | "-" ) unary | power ;
power = primary [ "**" power ] ;

primary = identifier "(" [ arg_list ] ")"
        | identifier "[" expression "]"
        | "new" base_type "[" expression "]"
        | array_literal
        | identifier
        | integer_literal
        | string_literal
        | char_literal
        | "true" | "false"
        | "(" expression ")" ;

arg_list = expression { "," expression } ;
array_literal = "[" expression { "," expression } "]" ;
type = base_type [ "[]" ] ;
base_type = "int" | "str" | "bool" ;

identifier = ( letter | "_" ) { letter | digit | "_" } ;
integer_literal = digit { digit | "_" digit } ;
string_literal = '"' { printable_char | escape_sequence } '"' ;
char_literal = "'" ( printable_char | escape_sequence ) "'" ;
escape_sequence = "\\" ( "n" | "r" | "t" | "0" | "\\" | "'" | '"' ) ;

comment = line_comment | block_comment ;
line_comment = "//" { printable_char } ;
block_comment = "/*" { any_char } "*/" ;
```
> [!warning]
> Грамматика _каноническая_: парсер дополнительно допускает скобки вокруг цели присваивания, например `(x) = 5`

> [!warning]
> Правый операнд `**` не может быть унарным выражением: `-b` и `!b` справа требуют скобок, например `a ** (-b)`. Отдельно запрещено `-2147483648 ** x`

> [!note]
> - **letter** -- латинские a-z и A-Z
> - **digit** -- цифры 0-9
> - **printable_char** -- любой печатный ASCII кроме служебного '\\' и перевода строки
> - **any_char** -- любой символ, включая перевод строки
> - **comment** -- `//` до конца строки или `/* ... */`, вырезается лексером и не участвует в разборе
> - **const** -- только для скалярных `int`, `bool` или `str`; значение вычисляется компилятором из литералов и ранее объявленных констант; вызовы функций, `new` и индексация запрещены

> [!important]
> Если тип возвращаемого значения `-> type` опущен, функция считается процедурой и может завершиться без `return` (`return;` использовать можно для преждевременного завершения). Если тип указан, функция обязана вернуть значение этого типа при любом раскладе.

## Организация памяти

Машинное слово -- 32 бита. Архитектура гарвардская: память команд и память данных физически раздельны, каждая однопортовая. Память данных адресуется байтами (`lw`/`sw` требуют адрес, кратный 4; байтовые `lb`/`lbu`/`sb` работают с любым), память команд -- номерами инструкций: PC и смещения переходов измеряются в словах. Скрытых флагов и служебных регистров нет: условия проверяются сравнениями и ветвлениями, ошибки времени исполнения -- `trap` с кодом причины. Прерываний в варианте нет: ввод-вывод потоковый, внешние события обрабатывать нечем и не нужно.

### Регистры

32 регистра общего назначения по 32 бита:

| Регистр | Имя | Роль |
| --- | --- | --- |
| `R0` | | константный ноль, запись игнорируется |
| `R1` | `RA` | адрес возврата |
| `R2` | `SP` | указатель стека |
| `R3` | `FP` | указатель кадра функции |
| `R4`-`R7` | | аргументы функции, `R4` также содержит результат |
| `R8` | `HP` | зарезервированный глобальный указатель кучи, не входит в пул временных регистров |
| `R9`-`R31` | | временные регистры |

Имена `RA`, `SP`, `FP`, `HP` -- соглашение транслятора; в машинном слове регистр -- всегда 5-битный номер. Нулевой `R0` даёт два «бесплатных» приёма: `addi Rd, R0, imm` -- загрузка константы, `add Rd, Rs, R0` -- пересылка значения.

### Память команд и данных
```text
       Регистры (32 x 32 бита)
┌──────────────────────────────┐
│ R0 : ноль                    │
│ R1 : RA  адрес возврата      │
│ R2 : SP  указатель стека     │
│ R3 : FP  указатель кадра     │
│ R4-R7 : аргументы            │
│ R8 : HP  указатель кучи      │
│ R9-R31 : временные           │
└──────────────────────────────┘

       Память команд (адресация словами)
┌──────────────────────────────┐
│ 0   : пролог                 │
│ 1.. : инструкции программы   │
│ ...                          │
└──────────────────────────────┘

       Память данных (RAM 1 МиБ, байтовая адресация)
┌──────────────────────────────┐◄── адрес 0
│ статика: литералы и const    │
├──────────────────────────────┤◄── static_end = начальный HP
│ куча: new, буферы input(),   │
│       конкатенация строк     │
├──────────────────────────────┤◄── HP, растёт вверх
│ свободно                     │
├──────────────────────────────┤◄── SP, растёт вниз
│ кадры стека                  │
└──────────────────────────────┘◄── размер RAM
```
Файл `.bin` содержит и код, и статику: 4 байта `static_size` (little-endian), затем `static_size` байт образа статики, затем instruction words. `static_size` кратен 4, включает нулевое слово и padding; instruction words также little-endian, остаток файла после образа должен иметь размер, кратный 4.

Загрузчик кладёт образ в память данных с адреса 0, загружает остаток в отдельную память команд с PC = 0, а размер RAM и начальный `SP` получает из настроек модели. Первое слово образа статики -- нулевое: на байт 0 ссылаются `str` без инициализатора, на слово по адресу 0 -- неинициализированные массивы.

Пролог выставляет `HP = static_end`; затем режим с `main` вызывает `main`, режим без `main` вызывает синтетическую функцию скрипта с обычным ABI-кадром; после возврата выполняется `halt`, который сообщает код из `R4`. Инструкции не читаются как данные, данные не исполняются: самомодификация невозможна.

Начальное состояние машины: PC = 0, регистры нулевые; модель перед первой инструкцией выставляет `SP` в размер RAM, `HP` выставляет пролог.

Память данных -- little-endian: младший байт слова по меньшему адресу. Заранее размеченных секций нет: статика кончается на `static_end`, куча растёт вверх от него без `free`, стек -- вниз от размера RAM; пересечение кучи и стека -- trap. Статика, не умещающаяся в диапазон знакового смещения `imm16` (32 КиБ), -- ошибка компиляции.

### Конструкции языка при компиляции и исполнении

**Литералы.** Целочисленный литерал (или значение `const`) в диапазоне `Imm` (-32768..32767) кодируется непосредственным операндом `addi Rd, R0, imm` и в память не попадает. Более широкое значение -- одно слово в статике, каждое использование -- `lw Rd, imm16(R0)`: слово одно на литерал, обращение -- одна команда. Строковый литерал -- плотные байты с терминатором `\0`; следующий после него адрес выравнивается вверх до кратного 4. Литерала шире одного слова в языке нет: `int` -- ровно 32 бита, константы вне 32-битного диапазона отвергаются на компиляции.

**Константы.** `const` вычисляется транслятором и исполняемого кода не создаёт: малые `int` и `bool` -- непосредственные операнды команд; широкие `int` -- слово статики; `str` -- строковый литерал в статике, на который ссылаются все использования константы.

**Переменные.** Изменяемых глобальных переменных в языке нет, статическая память под переменные не выделяется. Локальные переменные (и скриптовые в программе без `main`) живут на стеке, в кадре с базой `FP`: доступ -- `lw`/`sw` со смещениями от `FP`; параметры -- в `R4`-`R7`, с пятого -- в стеке, их кладёт и снимает вызывающий. На регистрах переменные не живут: регистры хранят только временные значения вычисляемых выражений. Для переменных нехватки регистров не бывает; пул временных конечен -- в предельном случае кодоген завершается ошибкой компиляции «временные регистры закончились».

**Процедуры.** Код всех функций -- в памяти команд. Вызов -- `jal` (адрес возврата в `R1`), возврат -- `jr R1`. Кадр: пролог `addi SP, SP, -8; sw FP, 4(SP); sw RA, 0(SP); addi FP, SP, 4` и выделение локальных; эпилог симметричен. Старый `FP` лежит по `0(FP)`, `RA` -- по `-4(FP)`, локальные -- начиная с `-8(FP)`. Аргументы 1--4 -- в `R4`--`R7`, результат -- в `R4`; аргументы с 5-го вызывающий кладёт в стек и снимает после возврата (в вызываемой 5-й -- по `4(FP)`). `R8` (`HP`) зарезервирован под глобальный указатель кучи и обновляется только процедурами выделения памяти; `R4`--`R7` и `R9`--`R31` могут быть испорчены.

**Прерывания.** Не поддерживаются: ввод-вывод -- потоковый через порты, векторов и обработчиков нет.

## Система команд

Система команд -- учебный 32-битный RISC, за основу взят RISC-IV из курса: фиксированная длина инструкции 32 бита, операции -- только регистр-регистр, память и ввод-вывод -- отдельные команды. Классификация: регистровая load-store машина, не аккумулятор и не стек. Арифметика не меняет скрытых флагов: каждая команда оставляет младшие 32 бита математического результата; условия проверяются `slt`/`seq` и ветвлениями; ошибки времени исполнения -- `trap` с кодом причины.

26 команд в пяти форматах (`R`, `I`, `S`, `B`, `J`): старшие 6 бит слова -- опкод, его старшие 2 бита задают класс формата; смещения переходов измеряются в инструкциях, константные поля -- 16 бит.

- арифметика (`R`): `add`, `sub`, `mul`, `div`, `mod`
- логика и сравнения (`R`): `and`, `or`, `slt`, `seq`
- константы (`I`): `addi`, `lui`, `ori`
- память (`I`/`S`): `lw`, `lb`, `lbu`, `sw`, `sb`
- ветвления (`B`): `beq`, `bne`
- управление: `jmp`, `jal`, `jr`, `halt`, `trap`
- ввод-вывод (PMIO): `in`, `out`

Полная спецификация -- побитовые раскладки форматов, таблицы опкодов, семантика каждой команды, trap-коды, оценка тактов и отличия от RISC-IV -- в [docs/ISA.md](docs/ISA.md).

## Тестирование

Тесты -- golden: эталонные файлы хранятся в репозитории, тест сравнивает фактический результат с эталоном и падает при расхождении. Сейчас эталоны покрывают фронтенд транслятора: для каждого примера из [examples/](examples/) в [tests/frontend/golden/ast/](tests/frontend/golden/ast) лежит эталонный дамп AST -- S-выражение, которое выдаёт `dump()` после разбора. Тест парсит пример, снимает дамп и сравнивает с файлом: любое изменение структуры программы видно в диффе. Семантические проверки (имена, типы, инициализация) покрыты юнит-тестами [tests/frontend/test_semantic.py](tests/frontend/test_semantic.py)

Алгоритмы из задания (каждый -- пример и его golden-файл AST):
- [hello.ps](examples/hello.ps) -- hello world
- [cat.ps](examples/cat.ps) -- эхо входного потока; программу останавливает модель при исчерпании ввода (вариант `stream`), а не сама программа
- [hello_user_name.ps](examples/hello_user_name.ps) -- спрашивает имя и здоровается
- [sort.ps](examples/sort.ps) -- читает список чисел и выводит его отсортированным
- [double_precision.ps](examples/double_precision.ps) -- арифметика двойной точности: 64-битное число как пара 32-битных слов в `int[2]`, сложение и вычитание с переносом и заёмом
- вариант `alg3`: [power_many.ps](examples/power_many.ps) -- возведение в степень для нескольких пар чисел, [glob_match.ps](examples/glob_match.ps) -- сопоставление текста с шаблоном через рекурсию (`*` в шаблоне)
- дополнительно: [equality.ps](examples/equality.ps) -- сравнение `int` и `str` (сравнение массивов семантика отвергает), [constants_demo.ps](examples/constants_demo.ps) -- `include` и константы


Для локальной установки проекта и инструментов разработки из корня проекта:
```bash
python -m pip install -e ".[dev]"
```

Запуск всех проверок:
```bash
python -m pytest
python -m pyright
python -m ruff check .
```

Чтобы ruff сам починил найденное, что умеет:
```bash
python -m ruff check . --fix
```

Для запуска только тестов фронтенда:
```bash
python -m pytest tests/frontend
```

Те же проверки запускаются в GitHub Actions. Как всё настроено и почему выбраны именно эти инструменты -- [docs/TOOLING.md](docs/TOOLING.md)
